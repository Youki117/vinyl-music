# Vinyl Player

一个以视觉为第一卖点的 Windows 本地音乐播放器：整屏是一张可随意更换的人物底图，左侧压一层向右雾化弥散的白色蒙版，蒙版上放置黑胶唱片与全套播放控件；黑胶中心的贴纸跟随底图自动切换。

## 使用

安装包在 `src-tauri/target/release/bundle/nsis/` 下，装完直接运行。

**加音乐**：把文件或文件夹直接拖进窗口；或按 `P` 打开曲库，点「加文件 / 加文件夹」。文件夹会递归扫描。也可以从命令行带文件启动（`vinyl-player.exe 某首歌.mp3`），或把音频拖到 exe 图标上——会直接开始播那首。

**曲库与歌单**：按 `P` 打开。左栏是「全部音乐 / 我喜欢的 / 最近播放 / 最常播放」四个自动歌单，下面是自建歌单（`＋` 新建，双击重命名）。右栏可搜索、按七种方式排序。右键曲目可以「下一首播放」、加入歌单、收藏、从曲库移除。

**歌单互通**：「导入歌单」读 m3u / m3u8，建一个同名歌单并保持文件里的顺序；路径失效时退回按文件名在曲库里找回——歌单常是从别的机器拷来的，路径早就不对了但文件名一般没变。「导出」把当前列表写成 m3u8。

**歌词**：优先用文件内嵌的歌词；没有就自动找旁边的同名 `.lrc`（`某首歌.mp3` 配 `某首歌.lrc`）。也可以把 `.lrc` 直接拖进窗口，按文件名挂到对应曲目上。编码自动识别，UTF-8 与 GBK 都读得了。

歌词若带词级时间戳（增强型 LRC，形如 `[00:12.34]<00:12.34>March <00:12.90>winds`），当前行会**逐字点亮**；普通逐行歌词整行高亮，与以前一样。间奏处（LRC 里那种空的时间戳行）高亮会自动撤掉，不会让上一句一直亮着。

**播放设置**：按 `E` 或点顶部工具栏。含 10 段均衡器（8 组预设）、0.5×–2× 变速（不变调）、睡眠定时器（可选播完当前曲目再停）、输出设备选择。

**换底图**（本产品的核心）：把图片直接拖进窗口，或右键黑胶唱片，或点右下角的星标。选完图皮肤面板会自动弹出，左边拖底图焦点，右边拖唱片取景、滚轮缩放。唱片中间的图默认跟着底图走，也可以单独指定另一张。还没设过底图时，唱片中心显示曲目自带的专辑封面。

**调蒙版**：皮肤面板的「蒙版」页可以调边缘位置、羽化宽度、不透明度、边缘蜿蜒、呼吸强度。**「随音乐波动」拉到 0 以上，白雾边缘就会跟着音乐做竖向 S 型起伏。**

**改文案**：「文案」页可以改标题、副标题、年份、署名。

### 混音与音轨剪辑

按 `X` 或点顶部工具栏的波形图标。可以在当前这首歌之上叠加其他音轨同时播放，并像剪视频一样编辑它。

**基本操作**

- 各自独立调音量，可单独静音、单独移除。
- 时间轴的横轴是**主音轨的时间**，片段上画着源文件对应位置的波形——剪辑要看得见波形，否则是盲剪。

**剪辑操作**

| 操作 | 怎么做 |
| --- | --- |
| 分割 | 把播放头挪到想切的位置，按「✂ 在播放头分割」 |
| 删除某段 | 点选片段 → 「删除片段」。**片段之间的空白就是静音** |
| 移动 | 拖片段中间部分 |
| 裁剪长度 | 拖片段的左右两端。拖左端会同时改变它从源文件的哪里开始放 |
| 复制 | 点选片段 → 「复制片段」，自动放到后面的空位 |
| 单段音量 | 选中片段后拖「片段音量」，时间轴上会画一条虚线标出被压过的段 |

**「只留副歌」的做法**：在副歌前后各分割一刀，再把两边的片段删掉。

每个片段边缘有 20ms 自动淡变，不会咔哒。同一层的片段不会重叠（一个音频元素放不了同一文件的两个位置），所有操作都自动避让。编排按主音轨保存，下次播这首歌自动恢复。

**全程只是实时混音，不改动也不产出任何音频文件**，原始文件始终原样不动。

### AI 配图（默认关闭）

皮肤面板 →「AI 配图」页。把当前歌的歌词交给文本模型总结成一段画面，再交给生图模型出图，出来直接当底图。

**不开这个开关，应用仍然全程离线、不发任何网络请求。**

两个接口都按 OpenAI 兼容格式调用（`/chat/completions` 与 `/images/generations`），所以填谁的都行——DeepSeek、智谱、月之暗面、通义，甚至本地跑的 Ollama + 生图服务。图像接口留空就复用文本那套配置。

几个设计上的取舍：

- **以歌词为主，不以音调为主**。歌词里有具体意象（"没有星星的夜空"），图像模型吃这个；音调只能给出"明亮/忧伤"这类形容词，出来的是通用壁纸。没歌词时退回歌名与专辑名。
- **每首歌只生成一次，永久缓存**。切走再切回直接复用，不重复花钱。想换就点「重新生成这首」。
- **后台生成，不阻塞播放**。生成期间照常听歌，好了自动淡入换上。
- **风格后缀里「主体偏右、左侧留白」是硬要求**，不是审美偏好——画面左侧要压白色蒙版，主体画在左边会被盖住。
- 密钥以明文存在本机配置文件里，请只填你愿意这样存放的密钥。

### 快捷键

| 键 | 作用 |
| --- | --- |
| `空格` | 播放 / 暂停 |
| `←` `→` | 快退 / 快进 5 秒 |
| `↑` `↓` | 音量 |
| `M` | 静音 |
| `L` | A-B 循环：依次是设 A、设 B、清除 |
| `P` | 曲库与歌单 |
| `S` | 皮肤面板 |
| `E` | 播放设置（均衡器 / 变速 / 定时） |
| `X` | 混音与音轨剪辑 |
| `Esc` | 关闭面板 |

面板的关闭方式按现代软件的习惯来：点面板外面、按 `Esc`、再按一次对应的快捷键、点面板自己的 ✕，四种都行。点外面关闭的那一下会被吞掉，不会顺手把底下的按钮也按了。传输栏和标题栏不算"面板外面"——混音面板开着时本来就要一边拖进度条一边看时间轴。

键盘上的媒体键（播放/暂停、上一首、下一首）也可用，托盘图标右键同样能控制播放。**任务栏与锁屏的系统媒体面板**会显示当前曲名、艺术家和专辑封面，那一排按钮也能直接控制播放。窗口位置和尺寸会记住，音量、播放模式、曲库、当前曲目也会在下次启动时恢复。

歌单里按住曲目上下拖动可以改顺序（只在自建歌单、且排序为「添加时间」时有意义）。

## 开发

```bash
npm install
```

前端可以脱离 Tauri 单独跑，调视觉与播放逻辑都不必等 Rust 编译：

```bash
npm run dev
```

完整应用（需要 Rust 工具链，见 [TECH-DESIGN.md §1.3](docs/TECH-DESIGN.md)）：

```bash
npm run tauri dev
```

## 校验

```bash
npm test
```

```bash
node scripts/compare-visual.mjs --diag
```

```bash
node scripts/verify-skin.mjs
```

| 脚本 | 作用 |
| --- | --- |
| `npm test` | 169 个单元测试，覆盖 LRC 解析（含词级时间戳）、m3u 解析与生成、文本判码、片段编辑、洗牌、曲库筛选排序、WAV 标签解码、取景换算、配色对比度、格式化 |
| `verify-real.mjs` | **用公开渠道的真实素材跑 37 项端到端检查**：真实 ID3 标签、外挂歌词、逐字推进、换底图联动、真实音频混音、m3u 导入。素材用 `fetch-real-assets.mjs` 下载 |
| `verify-ui.mjs` | **逐个按键的交互测试，46 项**：把每个面板、标题栏、传输栏里的控件都点一遍，并验证点外部关闭、面板互斥、Esc 收起、常驻操控件不误触等交互约定 |
| `verify-packaged.mjs` | **在装好的应用里跑 29 项检查**：fs 能力域、配置读写、曲库恢复、SMTC 系统媒体面板。开发模式走的是浏览器实现，测不到这些 |
| `smtc-probe.ps1` | 从系统侧查 Windows 媒体会话（须用 Windows PowerShell 5.1，pwsh 没有 WinRT 投影）。带 `-Action next` 可从系统面板按下按钮，验证事件回得到应用里 |
| `verify-audio.mjs` | 端到端跑通播放链路（五种音频格式）。需要 `tests/fixtures/` 下有测试音频 |
| `verify-mix.mjs` | 端到端验证两条音轨同时发声与片段剪辑 |
| `compare-visual.mjs` | 与参考图对拍。核对黑胶坐标（精确判据），断言蒙版确由 WebGL 画出，SSIM 作回归绊线 |
| `verify-skin.mjs` | 端到端走一遍换底图路径，验证贴纸联动与配色更新 |
| `fetch-real-assets.mjs` | 下载实测素材（CC 音乐、同步歌词、自由许可图片），来源见 `tests/real/SOURCES.md` |
| `make-word-lrc.mjs` | 由行级 LRC 派生逐字 LRC（**时间戳为插值，非人工打轴**），用于测试逐字渲染 |
| `analyze-ref.mjs` | 从参考图实测蒙版边缘剖面，产出着色器参数 |
| `reference-ceiling.mjs` | 测定参考素材自身的 SSIM 上限，用于判定对拍阈值该定在哪 |

> 除 `verify-packaged.mjs` 外，其余 `verify-*` 与 `compare-visual.mjs` 都需要 `npm run dev` 已在 1420 端口运行。

`verify-packaged.mjs` 测的是 `npm run tauri build` 出来的**装机版**：它自己负责关掉旧实例、铺设初始状态、冷启动应用（WebView2 的 `--remote-debugging-port`）、跑完再关掉。几项判定只在冷启动下成立，所以不能连到一个已经跑着的实例上。

用真实素材跑出来的缺陷记录在 [FEATURE-PARITY.md §4.2](docs/FEATURE-PARITY.md)。

## 结构

```
src/
├─ platform/    唯一允许 import @tauri-apps/* 的地方；Tauri 与浏览器双实现
├─ stage/       渲染层：舞台缩放、底图、蒙版着色器、颗粒
├─ ui/          内容层组件与浮层面板
├─ audio/       播放引擎、频谱分析、波形峰值、元数据、片段模型
├─ skin/        皮肤模型、取景换算、自动配色
├─ lyrics/      LRC 解析（含词级时间戳）
├─ lib/         无依赖小工具：时间格式化、m3u、文本判码
└─ store/       Zustand：library / player / skin / mix / ai
src-tauri/      Rust 外壳，只做目录递归扫描与窗口
```

## 在线音源

搜索与歌词开箱即用。**解析播放地址需要一份音源脚本，本仓库不附带** —— 聚合音源
脚本原样分发的风险落在仓库上，所以留给使用者自己提供：

- 在「在线音乐」面板点**导入音源**选一个 `.js` 脚本，不需要重新构建；
- 或把脚本放进 `src/source/builtin/`（该目录的 `*.js` 已在 `.gitignore` 中），
  重新构建后随应用一起发布。

没有脚本时应用照常工作，只是点播放时拿不到地址。协议与宿主实现见
[src/source/builtin/README.md](src/source/builtin/README.md)。
