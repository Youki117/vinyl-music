## 1. 产品概述

### 1.1 一句话定位

一个**以视觉为第一卖点的 Windows 本地音乐播放器**：整屏是一张可随意更换的人物底图，左侧压一层向右雾化弥散的白色蒙版，蒙版上放置黑胶唱片与全套播放控件；黑胶中心的唱片贴纸跟随底图自动切换。

### 1.2 背景

用户已有一份用 Figma Make 生成的简版实现（保存在 `design-ref/figma-make/`），但**没有还原目标效果**，主要差距有三处：

| # | 目标效果 | Figma 版本现状 | 见文件 |
| --- | --- | --- | --- |
| D1 | 白色蒙版右缘是一团**不规则、羽化、雾化弥散**的边界，与人物照片自然融合 | 一条**垂直硬边**，白区与暗区生硬拼接 | `design-ref/figma-make/figma-output-hard-edge.png` |
| D2 | 人物底图**铺满整个画布**，白色蒙版半透明地压在它上面（透过白区仍能隐约看见花草） | 底图仅在"导入背景"后作为两块独立背景分别铺在左右两半 | `design-ref/figma-make/index.css:20-21` |
| D3 | 黑胶贴纸内容 = 当前底图的一块取景 | 贴纸写死为一张固定图片的负偏移裁切 | `design-ref/figma-make/index.css:30` |

此外 Figma 版本只是一个**静态外观 demo**：没有真实音频播放、没有音乐文件、没有歌词、没有播放列表，控件全是不通电的假按钮。

### 1.3 目标用户与场景

- **主要用户**：本产品作者本人。手上有一批本地音乐文件和一批喜欢的人物图（游戏 CG / 二次元 / 摄影作品），希望一边听歌一边把喜欢的图当"专辑封面"看。
- **典型场景**：
  - 双屏工作时，把播放器丢到副屏全屏挂着，当会动的桌面壁纸兼播放器。
  - 换了一张新图，30 秒内让它成为播放器的整体皮肤（底图 + 唱片贴纸 + 文字配色一起变）。
  - 需要一个**能真正当日常播放器用**的东西，而不是只能截图好看的 demo。

### 1.4 设计原则

1. **视觉优先**：任何功能都不得破坏画面。功能按钮宁可藏起来靠悬停/快捷键唤出，也不在画面上堆 UI。
2. **小巧精致**：安装包目标 < 20MB，冷启动 < 1.5s，空闲内存 < 350MB（原写 200MB，实测不可能，见 §7 注）。不引入重型框架、不引入数据库、不做插件系统、不做账号体系。
3. **不重复造轮子**：能用成熟开源库解决的（元数据解析、波形、LRC 解析）直接用；只有"雾化蒙版"和"音频驱动波浪"这两块没有现成轮子，自己写。
4. **一切皆可换皮**：底图、贴纸、标题文案、蒙版参数、文字配色全部是数据，不是硬编码。

## 2. 目标与非目标

### 2.1 目标（本项目要做的）

- G1 像素级还原目标效果图，尤其是 D1 的雾化边缘。
- G2 具备一个正常本地音乐播放器该有的全部功能（见 §5 F1–F8）。
- G3 底图与唱片贴纸可随意切换，且二者联动。
- G4 为"蒙版跟随音乐波动"预留完整的技术通路，后续开启不需要重写渲染层。

### 2.2 非目标（明确不做）

| 不做 | 原因 |

| ~~接入网易云 / QQ 音乐 / Spotify 等在线曲库~~ | **2026-08-19 推翻，已在做。** 原因不成立了：没有自己逆向，而是原样引入洛雪的 musicSdk（`src/vendor/lx-music/`）负责搜索/歌词/歌单，播放地址交给用户可换的音源脚本。以本文档为准的是 [REQUIREMENTS](./REQUIREMENTS-2026-08-18.md) §8 |

## 3. 核心概念与术语

统一以下叫法，后续文档与代码命名一致：

| 术语 | 英文 / 代码名 | 含义 |
| --- | --- | --- |
| 底图 | `backdrop` | 铺满整个画布的人物图片，是皮肤的主体 |
| 蒙版 / 白色蒙版 | `veil` | 压在底图上的浅色半透明层，左侧近乎不透明，向右雾化消失 |
| 雾化边缘 | `mist edge` | 蒙版右侧那条不规则、有噪点感的过渡带，本产品的视觉命门 |
| 黑胶 | `disc` | 左侧那张会转的黑色唱片 |
| 唱片贴纸 | `label` | 黑胶正中央的圆形图片区域，内容取自底图 |
| 取景框 | `labelFocus` | 从底图上裁出贴纸的那个正方形区域（位置 + 缩放） |
| 皮肤 | `skin` | 底图 + 取景框 + 蒙版参数 + 文字配色 + 标题文案 的一整套配置 |
| 曲库 | `library` | 用户导入的本地音频文件集合 |

### 4.1 画布与图层模型

整个界面是**一块固定比例的舞台**（设计基准 1220 × 688，约 16:9），按窗口大小整体等比缩放居中，四周留黑边。所有元素坐标都在这个基准坐标系里，保证任何分辨率下版式与效果图一致。

从下到上的图层顺序：

| 层 | 名称 | 内容 | 备注 |
| --- | --- | --- | --- |
| L0 | 底图层 | 人物图，等比裁切铺满 | 切换底图时交叉淡入 |
| L1 | 蒙版层 | 白色蒙版 + 雾化右缘 | **本产品的核心视觉，见 §4.3** |

### 4.3 雾化边缘的验收标准（D1，最高优先级）

这是整个项目"像不像"的唯一关键，单独立标准：

- A1 蒙版右缘**不得出现任何可见直线**。将画面转灰度后沿水平方向求梯度，边缘带内不应存在贯穿高度 > 30% 的连续等值线。
- A2 过渡带宽度不小于画布宽度的 12%（约 150px @1220），且宽度本身沿竖直方向是**变化的**，不是等宽。
- A3 过渡带内可见细微的云絮状明暗起伏（噪点/柏林噪声质感），不是纯线性渐变。
- A4 白区内可**隐约透出底图内容**（目标图里能看见花草轮廓），蒙版不透明度上限 92%，不得做成纯白遮死。
- A5 版式对拍：黑胶圆心与半径相对参考图的偏差 ≤ 6px（实测 0/1/0px），歌词、进度条、控制条位置偏差 ≤ 3px。

> **关于 SSIM 阈值的修订（2026-08-15）**
>
> 本文档初稿写了「SSIM ≥ 0.92」，那是在拿到参考素材之前定的，实测证明它由构造上就不可达，已作废。
>
> 依据：`scripts/reference-ceiling.mjs` 把用户提供的两张参考图（同一份设计的两次录屏）**互相**对拍，
> 只得到 **0.673 / 0.692**。这是本套素材的理论上限，任何实现都不可能超过。原因是参考图为低分辨率
> 录屏——歌词字形已糊到辨认不出（「震颤」录成「曩夏」），黑胶是照片纹理而非程序生成。
>
> 更要紧的是这个指标会**反向误导**：实测把黑胶纹路做得更接近真实唱片之后，该区 SSIM 反而从
> 0.245 掉到 0.204。继续追这个数字只会把画面推向更糊的方向。
>
> 现行做法：SSIM 降级为回归绊线（阈值 0.66，当前 0.70，用于发现布局塌陷、图层丢失、字体未加载），
> 真正的保真度由上面 A5 的坐标偏差与 A1–A4 的雾化边缘量化指标保证。

## 5. 功能需求

优先级定义：**P0 = 首个可用版本必须有**；**P1 = 正式版必须有**；**P2 = 后续迭代**。

### F1 播放引擎 — P0

- F1.1 支持格式：MP3、FLAC、WAV、M4A/AAC、OGG。
- F1.2 播放 / 暂停 / 停止；上一首 / 下一首。
- F1.3 进度拖拽跳转，精度 ≤ 100ms。
- F1.4 音量调节（0–100）与静音，音量曲线用感知对数曲线而非线性。
- F1.5 播放模式循环切换：列表循环 → 单曲循环 → 随机 → 顺序播放（播完停止）。随机需为"洗牌不重复"，一轮内不重复播放同一首。
- F1.6 曲目结束自动进入下一首，切换间隔 < 200ms。**已达成**：起播 1.5 秒后预取下一首，
  实测切歌 29ms 且命中时不再读文件（`scripts/verify-switch.mjs`）。
- F1.7 记忆退出时的曲目、播放位置、音量、播放模式，下次启动恢复（默认不自动播放）。
- **验收**：连续播放 20 首不同格式曲目无崩溃、无内存增长超过 50MB；进度条拖拽 50 次音频不出现爆音。

### F2 曲库与播放列表 — P0

- F2.1 通过文件对话框添加**文件**或**整个文件夹**（递归扫描）。
- F2.2 支持窗口内拖拽文件/文件夹导入。
- F2.3 读取并展示元数据：标题、艺术家、专辑、时长、内嵌封面。元数据缺失时回退用文件名。
- F2.4 播放列表抽屉：列表展示、双击播放、右键移除、拖拽排序、搜索过滤。
- F2.5 曲库持久化到本地，重启后仍在；源文件被删除时列表项标灰并可一键清理。
- F2.6 扫描 1000 首曲目应在 15s 内完成，且过程中界面不卡顿（进度可见）。
  **实测 50.2s，未达标**（`scripts/perf/dbg-library.mjs`，1000 首合成曲库每首约 0.6MB，
  装机版）。界面不卡这一半做到了：面板开着导入只比关着慢 6%。慢的是"每首都要把整个
  文件过一遍 IPC 再解析"，而解标签其实只需要文件头 —— 治本要 `readSlice`，见
  `docs/TECH-DESIGN.md`。并发从 1 提到 2 已经把 72.4s 压到 50.2s，再往上峰值内存会失控。
- **验收**：导入含 500 个文件的嵌套文件夹，全部曲目元数据正确，无重复项。

### F3 进度与波形 — P0

- F3.1 进度条显示当前位置 / 总时长。
- ~~F3.2 进度条上方叠加当前曲目的**波形峰值图**（E8）~~ —— **已取消，元素删除**。
  实现时把它做成了跟随播放头的 118px 窗口，于是整个窗口在屏幕上横向滑动、窗口内部
  又在滚，双重运动看着像故障。参考图是单帧，本来就看不出运动，"跟着播放头走"是
  从"那一帧里它俩恰好重合"推出来的错误推断。删除后视觉对拍 SSIM 反而从 0.7283
  升到 0.7299 —— 说明它原来的位置就和参考图对不上。
- ~~F3.3 波形峰值需缓存~~ —— 缓存机制保留（`audio/peaks.ts`），但改由**混音面板**按需
  取用；播放路径不再为了画一张没人看的图去解码整首歌（约 16MB PCM/首）。
- ~~F3.4 波形尚未算出时显示占位静态图形~~ —— 随 F3.2 取消。

### F4 黑胶 — P0

- F4.1 播放时黑胶匀速顺时针旋转（约 20s/圈）；暂停时**就地停住**，恢复时从停住的角度继续，不得回弹归零。
- F4.2 唱片贴纸随黑胶一同旋转。
- F4.3 切歌时贴纸做一次短促的转场（淡出 → 换图 → 淡入，总时长 ≤ 400ms）。
- F4.4 点击黑胶 = 播放/暂停。

### F5 皮肤系统 — P0（**核心需求**）

- F5.1 用户可导入任意本地图片作为底图（PNG/JPG/WebP/AVIF），单张不超过 30MB。
- F5.2 底图以"等比裁切铺满"方式呈现，可调整焦点（避免人脸被裁掉）。
- F5.3 **唱片贴纸默认自动取自当前底图**：默认取景框为图片中心偏上的正方形区域（贴合"人物头部通常在上半部"的经验）；用户可拖拽 / 滚轮缩放调整取景框，所见即所得。
- F5.4 用户也可为贴纸单独指定另一张图片（脱离底图联动）。
- F5.5 更换底图时，贴纸、蒙版着色、文字配色一并更新，整体呈现为一次交叉淡入转场（≤ 600ms）。
- F5.6 文字配色可从底图自动取色（保证与蒙版底色的对比度 ≥ 4.5:1），也可手动覆盖。
- F5.7 皮肤可保存为具名条目并快速切换；内置 1 套默认皮肤。
- F5.8 蒙版参数（边缘位置、羽化宽度、不透明度、色温）在设置面板中可调，实时预览。
- **验收**：准备 5 张不同色调（明亮/昏暗/高饱和/低饱和/纯色背景）的人物图，逐一切换，每张都能得到文字清晰可读、贴纸取到人物主体的结果，且无需手动调参。

### F6 歌词 — P1

- F6.1 自动加载同名 `.lrc` 文件；其次读取音频文件内嵌歌词。
- F6.2 支持标准 LRC 时间标签，含同一行多时间戳、以及 `[offset:]` 偏移。
- F6.3 按目标图样式呈现：竖排 6 行、居中、当前行加粗加深、上下行渐隐。
- F6.4 滚动为平滑缓动而非跳变；点击某行跳转到对应时间。
- F6.5 无歌词时歌词栏自动隐藏，其余版式不位移。
- F6.6 歌词偏移可在播放中 ±0.5s 步进微调并记住。

### F7 音质与输出 — P1

- F7.1 输出设备选择（系统默认 / 指定设备）。
- F7.2 淡入淡出：切歌与暂停时做 80ms 淡变，消除咔哒声。
- F7.3 可选的 10 段均衡器，含若干预设，默认关闭。
- F7.4 音量归一化，默认关闭。**已实现，但没照「无标签时按峰值估算」做** ——
  峰值和响度基本无关（一下鼓击就能顶到 0dBFS，按它归一化等于没归一化）。
  改为 ReplayGain 标签优先，无标签时按 ITU-R BS.1770 / EBU R128 量整体响度；
  峰值只用于防削波。理由与实测见 REQUIREMENTS §14 与 `src/audio/loudness.ts`。

### F8 系统集成 — P1

- F8.1 无边框窗口，自绘标题栏，支持拖拽移动、双击最大化、边缘缩放。

### ~~F10 蒙版音频波动~~ — **已实现，后又整体删除**

曾经做出来过：16 段频谱包络驱动蒙版右缘做 S 型行波，快起慢落，掉帧自动降八度。
**删除原因有两条，缺一不可：**

1. **观感达不到预期**（用户评价"和我预想的差不少"）。
2. **代价太大。** 实测（两次冷启动，播放同一首歌，采样 12 秒）：

   | | CPU |
   | --- | --- |
   | 律动开（60fps 档） | 38.6% |
   | 律动关（12fps 档） | 27.8% |

   播放本身的基线已占 26–30%，律动大约是播放时总 CPU 的**四分之一到三分之一**。
   （两次差值 6.3 / 15.2，噪声约 ±3pp，别当精确值。）

删掉的是**驱动源**，不是形状：`veil.frag` 里那条 S 形波的数学原样保留，只是不再由频谱驱动，
改由静态参数 `ripple`（原 `breath`）控制幅度。以后想换别的驱动方式，接回同一个位置即可。

一并移除：`audio/analyser.ts`、引擎里旁路的 AnalyserNode、蒙版的时钟订阅。

**顺带把蒙版整体改成"只在参数变化时画一帧"**，因为逐帧渲染本身也不便宜：

| 蒙版的空闲 CPU 增量 | |
| --- | --- |
| 逐帧渲染 | 9.2% |
| 一次性渲染 | **0.2%** |

代价是 WebGL 上下文要开 `preserveDrawingBuffer`（否则画一次之后缓冲内容按规范是未定义的），
约多占 25MB 内存。拿 25MB 换 9 个百分点 CPU，权衡后接受。

> 没有换成一张静态 PNG，是因为边缘位置、羽化、蜿蜒、颜色四个参数都还要能调 ——
> 三色自动取色正是靠改颜色参数生效的。一次性渲染的开销本来就和贴张图差不多。

### F11 AI 配图 — P1（**差异化功能**）

把当前曲目的歌词交给文本模型总结成一段画面描述，再交给生图模型出图，出图直接成为底图。

- F11.1 **默认关闭**。不开这个开关，应用仍然全程离线、不发起任何网络请求（§7 的承诺因此仍然成立）。
- F11.2 两个接口均按 OpenAI 兼容格式调用（`/chat/completions` 与 `/images/generations`），用户自行填写 Base URL、密钥、模型名，因此 DeepSeek、智谱、月之暗面、通义、本地 Ollama 都能接。
- F11.3 请求必须从 Rust 侧发出。这些服务基本不给浏览器来源发 CORS 头，从 WebView 直接 `fetch` 会被拦，外部域名也过不了 CSP。
- F11.4 **以歌词为主体，不以音调为主体**。歌词含具体意象（"没有星星的夜空"），图像模型吃这个；音调只能得到"明亮/忧伤"这类形容词，产出的是通用壁纸。无歌词时退回歌名与专辑名。
- F11.5 **每首曲目生成一次，永久缓存**。图像接口一次 10–30 秒且要花钱，绝不能每次播放都调。
- F11.6 **绝不阻塞播放**。后台生成，完成后走既有的 600ms 交叉淡入换上。
- F11.7 固定风格后缀，保证所有生成图看起来同属一套。其中**"人物主体位于画面右侧、左侧留出大面积简洁背景"是硬约束**——画面左侧要压白色蒙版，主体画在左边会被盖掉。
- F11.8 展示模型总结出的画面描述，让用户判断它有没有理解对。
- F11.9 密钥以明文存于本机配置文件，面板上须明示，不做安全存储的承诺。
- **验收**：填好配置后为一首有歌词的曲目生成，得到的图主体在右、左侧留白，切歌再切回时直接复用缓存不重复调用。

## 6. 关键交互流程

### 6.1 首次启动

1. 显示内置默认皮肤，播放列表为空，中央提示"拖入音乐文件或点此添加"。
2. 用户拖入文件/文件夹 → 扫描进度条 → 自动选中第一首但**不自动播放**。
3. 提示一次"右键黑胶可更换底图"，之后不再提示。

### 6.2 更换底图（核心路径，要求 ≤ 3 步）

1. 右键黑胶（或从设置面板）→ 选择图片。
2. 弹出取景调整浮层：左侧预览整张图与底图焦点，右侧预览圆形贴纸取景，均可拖拽。默认值即已可用，用户可直接确认。
3. 确认 → 全画面交叉淡入到新皮肤，自动保存。

### 6.3 播放状态机

```
        ┌──────────┐  load()   ┌──────────┐
        │  Empty   │──────────▶│ Loading  │
        └──────────┘           └────┬─────┘
                                    │ ready
                          error ┌───▼──────┐  play()  ┌──────────┐
                        ┌───────│  Paused  │─────────▶│ Playing  │
                        │       └──────────┘◀─────────└────┬─────┘
                        │             ▲       pause()      │ ended
                   ┌────▼─────┐       │                    │
                   │  Error   │       └────────────────────┘
                   └──────────┘         next() / repeat
```

- `Error` 状态：在曲名位置显示错误原因，2s 后自动跳下一首（连续 3 首失败则停止并提示）。
- 任何状态下黑胶的旋转都只由 `Playing` 驱动。

## 7. 非功能需求

| 项 | 指标 | 说明 |
| --- | --- | --- |
| 安装包体积 | < 20MB | 目标 8–15MB |
| 冷启动到可交互 | < 1.5s | |
| 常驻内存 | 空闲 < 350MB / 播放峰值 < 550MB | 整棵进程树的 Private Bytes。**原定的 "< 200MB" 是错的，已作废** —— 见下方注 |
| 空闲 CPU | < 3% | 暂停且窗口可见时；渲染循环需在暂停时降频 |
| 播放中 CPU | < 8% | **未达标**：实测 26–30%（不含已删除的蒙版律动）。蒙版本身已降到 0.2%，剩下的是音频解码、进度更新与合成 |
| 渲染帧率 | 60fps | 1080p 窗口，中端集显 |
| 音频延迟 | 点击到出声 < 150ms | |
| 崩溃率 | 连续播放 8 小时无崩溃、无内存泄漏 | |
| 系统要求 | Windows 10 1809+ / Windows 11，x64 | 依赖 WebView2 运行时（Win11 已内置） |
| 可访问性 | 全部功能可纯键盘完成；所有图标按钮有无障碍标签 | 不做屏幕阅读器深度适配 |
| 隐私 | 不采集任何数据，不上报，无账号 | ~~"默认完全离线"~~：**2026-08-19 起不再成立**。在线音源（§2.2 已推翻的那条）会主动访问音乐平台的接口；本地播放路径仍然全程不联网。AI 配图（F11）依旧默认关闭 |

> **关于内存指标为什么改了。** 原来写 "< 200MB"，并在 §10 记了 "实测约 40MB ✅"。
> 那个 40MB 只量了 Tauri 主进程，把 WebView2 拉起来的一整棵 Chromium 进程树漏掉了 ——
> 而内存几乎全在那棵树里。这个指标在装机版上从来没成立过，只是没人去数进程。
>
> 实测的地板（`scripts/perf/dbg-floor.mjs`，冷启动干净 profile，两次取平均）：**一个什么都不画的
> 空白页，整棵树就要 323MB**。这跟我们写了什么代码无关，是 Chromium 多进程模型
> 本身的成本，Electron 系的播放器（洛雪、MusicFree）同样绕不开。所以 200MB 在
> WebView2 上不是"没优化到"，是物理上不可能。
>
> 新指标是**目标**不是现状：当前实测空闲 392MB、峰值 810MB，两条都没达标。
> 已实测能把它降到 281 / 463MB 的两个 WebView2 启动参数（`--in-process-gpu`、
> `--js-flags=--max-old-space-size`）是拿稳定性换的，权衡后没有采用，理由见
> [技术设计文档 §1.2](./TECH-DESIGN.md)。要摘掉这两个 ❌，得先补长跑验证再开参数。
>
> 量法固定为"整棵进程树的 Private Bytes"，避免再出现口径分歧。

## 8. 版本规划

| 里程碑 | 目标 | 范围 | 预估 |
| --- | --- | --- | --- |
| **M0** 骨架 | 空窗口能跑起来 | 工程搭建、Tauri 外壳、无边框窗口 | 0.5 天 |
| **M1** 视觉还原 | **静态画面与效果图对拍达标** | L0–L3 全部图层、雾化边缘、全部 UI 元素（假数据） | 2–3 天 |
| **M2** 播放引擎 | 能当播放器用 | F1、F2、F3、F4 | 2 天 |
| **M3** 皮肤系统 | 换图能力打通 | F5 | 1.5 天 |
| **M4** 完整版 | 正式可用 | F6、F7、F8、F9 | 2 天 |
| **M5** 波浪 | 蒙版活起来 | F10 | 1.5 天 |
| **M6** 发布 | 出安装包 | 打包、图标、签名（可选）、README | 0.5 天 |

M1 排在播放功能之前，是因为**"像不像"是本项目唯一不可妥协的指标**，越早锁死风险越低；若 M1 的雾化边缘方案走不通，整个技术选型需要重来，不应该在写完播放器之后才发现。
