# 与主流播放器的功能对照

以 QQ 音乐 / 网易云音乐的本地播放部分，以及两个热门开源项目为基准：

| 项目 | ★ | 定位 | 许可证 |
| --- | --- | --- | --- |
| [SPlayer](https://github.com/SPlayer-Dev/SPlayer) | 7.4k | 仿网易云，含本地播放模式 | **AGPL-3.0** |
| [musicat](https://github.com/basharovV/musicat) | 934 | 本地优先，Tauri | **GPL-3.0** |

> ⚠️ 两者均为传染性开源许可证，**只作功能参照，不复制任何代码**。

---

## 一、明确不做（与本地播放器定位冲突）

| 功能 | 不做的理由 |
| --- | --- |
| 扫码 / 手机号登录、每日签到 | 需要账号体系 |
| 云盘上传、云盘歌曲播放与纠正 | 需要服务端 |
| Subsonic / Navidrome / Jellyfin 等流媒体 | 需要外部服务器 |
| 评论区、MV 与视频播放 | 超出播放器职责 |
| Last.fm Scrobble | 需要联网上报，与「全程离线」冲突 |
| PWA / 移动端适配 | 只做 Windows |

这些在 PRD §2.2 已列为非目标，此处不改。

## 四、实测记录

`scripts/verify-audio.mjs` 用 ffmpeg 生成的五种格式（wav / mp3 / flac / ogg / m4a）真跑一遍播放链路，12 项全通过。过程中发现并修掉两个缺陷：

- **WAV 中文标签乱码**：music-metadata 读 RIFF LIST/INFO 块时按 7 位 ASCII 处理，会抹掉每个字节的最高位（实测「测试曲目一」的 UTF-8 字节 `E6 B5 8B…` 变成 `f 5 \x0b…`）。这是有损的，拿到字符串再转码救不回来，只能重读原始字节。已自行实现 `parseWavInfo`，优先 UTF-8、失败退 latin1；另加 `looksCorrupt` 兜底，任何格式解出控制字符都退回文件名，宁可显示文件名也不显示乱码。
- **未播放时总时长显示 00:00**：界面取的是引擎时长，而引擎在真正载入曲目前是 0。改为回退到元数据里的时长。
