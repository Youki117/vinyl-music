# 右侧栏与曲库细化需求基线（2026-08-21）

## 1. 文档目的

本文件记录 2026-08-21 已确认的界面细化范围，作为本轮实现、测试和回滚对照。需求发生冲突时，遵循用户明确指定的规则：**编号越大代表越新的要求，最新要求覆盖较早要求**。

截图和 `目标效果.html` 只提供视觉与交互参考，不是完整产品规范；主界面、黑胶、现有按钮位置和整体视觉语言以当前播放器为准。所有新增或调整后的控件继续沿用项目现有的黑金、极简线条风格，不混入另一套 UI 风格。

## 2. 最终范围与验收标准

### 2.1 音源可用状态

- 音源管理页不再显示“可用解析”等常驻状态文字。
- 可用状态显示为一个小绿点；不可用状态使用弱化的中性色状态点。
- 鼠标悬停状态点时，通过浮层文字解释状态，同时保留无障碍标签。

### 2.2 歌单删除

- 曲库左侧“歌单”标题行仅放置“删除”和“新建”两个同规格线条图标按钮。
- 删除按钮只针对当前选中的用户歌单；系统虚拟列表或没有选中用户歌单时不可用。
- 不给每个歌单单独配置一键删除按钮，避免误触。
- 删除前必须显示应用内二次确认，明确说明只删除歌单，不删除歌曲文件。

### 2.3 自动从底图取色

- “自动从底图取色”由原生勾选框改成与项目现有设置控件一致的开关样式。
- 保留原有状态与业务逻辑，仅改变控件表达和交互反馈。

### 2.4 主标题文字位置

- 主标题、第二行、第三行与署名使用固定的垂直槽位。
- 播放歌曲后即使某一行内容为空，也要保留该行高度，不能导致专辑、年份或署名上下跳动。
- 长歌名可以按现有规则缩放或截断，但其起始位置和后续文字槽位必须稳定。

### 2.5 曲库与歌单按钮

- 歌单标题行按钮大小统一为现有“新建歌单”加号按钮的规格。
- 删除每个歌单右侧的导出按钮；当前版本不提供歌单导出入口。
- 歌单列表行仅显示歌单名称和歌曲数量。

### 2.6 底图选择与自定义历史

- 内置底图、自定义历史和选择入口位于同一条横向、不换行的缩略图轨道中。
- 可视宽度约为四张半缩略图，让下一张露出一半作为可滚动提示。
- 鼠标滚轮在该区域内转换为横向滚动，滚动条不常驻显示。
- 顺序固定为：四张内置底图 → 已记录的自定义底图 → `+自定义` 入口。
- 用户选择过的自定义底图保留为可再次点击的历史项；沿用当前实现的容量限制与去重行为。
- 原“+选择”文字改为“+自定义”。

### 2.7 在线歌单导入迁移

- 在线页面只保留“在线搜索”和“音源管理”两个标签，不再显示“歌单导入”标签。
- QQ 音乐、网易云音乐等平台的歌单链接/文案/ID 导入功能迁移到“音乐库与歌单”页面。
- 曲库左侧“歌单”标题行由旧的“导入 + 新建”改为“删除 + 新建”。
- “导入歌单”作为一个完整列表入口，自动衔接在最后一个用户歌单之后；不是标题行下载图标。
- 点击“导入歌单”后，在曲库右侧主区域显示迁移后的解析、预览、全部播放和导入本地歌单流程。
- 导入成功后，歌单出现在左侧歌单列表中，并优先切换到新导入的歌单。
- 不复制两套实现；现有在线导入视图应提取或复用为曲库内可调用的组件。
- 本地 M3U/文件导入的底层能力可保留，但不再占用本轮指定的歌单标题行入口。

## 3. 冲突裁决记录

- 较早的“把导入/导出做成小图标”被最新要求覆盖：标题行最终为“删除 + 新建”，导出入口删除。
- 较早的“选择底图放在内置底图最后并全部列出”被最新要求覆盖：最终为只显示约四张半宽度的横向滚动轨道，入口文字为 `+自定义`。
- 较早的“搜索页面保留导入歌单标签”被最新要求覆盖：最终在线页仅保留“在线搜索”和“音源管理”，歌单导入迁至曲库。
- 较早的“删除歌单文字按钮”被最新要求覆盖：最终使用标题行共享线条图标按钮，并增加应用内二次确认。

## 4. 实施边界

- 不修改主界面现有黑胶布局和主要播放控件布局。
- 不新增第三方依赖，不更换状态管理、测试框架或构建工具。
- 不删除现有底层能力，除非本文件明确要求移除可见入口。
- 不提交 `artifacts/`、`release-test/`、`src-tauri/target-*`、用户图片、`assets/` 或 `目标效果.html`。
- 先保留本地 Git 回滚提交，再进入本轮新实现；不推送远端。

## 5. 验证要求

- TypeScript/Vite 构建通过。
- 相关单元测试及全量测试通过。
- 实际桌面界面验证：两标签在线页、曲库导入入口、歌单二次删除、音源状态点、取色开关、主标题固定槽位、横向底图历史。
- 对照用户截图和本文件完成同状态截图比较，更新根目录 `design-qa.md`；存在 P0/P1/P2 问题时不得判定通过。
