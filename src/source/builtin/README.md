# 内置音源目录

**这个目录在开源仓库里是空的**，构建不依赖它。

## 为什么是空的

聚合音源脚本从各音乐平台取播放地址，把这类脚本原样收进公开仓库分发，法律风险
落在仓库上。所以脚本不入库（`.gitignore` 里排掉了 `*.js`），改由使用者自己提供。

## 怎么用

两条路，效果一样：

1. **界面里导入** —— 「在线音乐」面板的「导入音源」，选一个 `.js` 脚本。这条路
   不需要重新构建，也是普通用户该走的路。
2. **放进这个目录** —— 把脚本放成 `src/source/builtin/*.js`，重新构建，它会被
   自动收进产物，启动时自动载入。自用构建可以这么做。

没有脚本时应用照常工作：搜索和歌词不依赖音源脚本，只有**解析播放地址**依赖它
（`boot.ts` 对此有降级，只在控制台警告）。

## 脚本要满足什么

走的是洛雪音乐助手那套自定义音源协议，宿主实现见 `../userApi/protocol.ts`。
脚本跑在 **Worker** 里：没有 DOM、没有 `window`、没有 Tauri IPC，网络请求由主线程
代发。宿主提供 `globalThis.lx` 的 `EVENT_NAMES` / `request` / `on` / `send`；
`lx.utils`（crypto、zlib、buffer）也在，但不是每个脚本都用得上。

换脚本之后建议跑一次 `node scripts/verify-source.mjs` 确认链路通。
